# 演示与验收

## 三分钟主线

1. 载入虚构示例。解释 300 报名、240 条签到、210 到场，其中 180 名报名者和 30 名未报名到场者。
2. 点 M3：60% = 180 / 300，不能直接用 M2 / M1。
3. 推荐渠道问题 → 参数确认 → 图表：65/75=86.7%、50/75=66.7%、40/75=53.3%、25/75=33.3%。点图展示源文件行号。
4. 修改问卷范围为全部到场，保存 v2：回收率 50% → 42.9%。旧数字及已保存图表能回放。
5. 注入故障：只改内存副本，不破坏原文件；数字、引用规则失败，因果词提示人工审查。关闭注入恢复。
6. 导出报告和 JSON，在附录找公式、hash、版本和原始行。HTML 可打印 PDF。

讲解边界：“这是事实层复盘，告诉你发生了什么和哪些说法缺依据，不替你猜管理原因。”

## 换文件：真实依赖变化

`fixtures/` 全部是虚构数据：

| 文件 | 用途 |
|---|---|
| registration.csv | 300 人报名 |
| attendance.csv | 240 条签到，含 30 条同人重复 |
| feedback.csv | 90 份，均分 4.2 |
| attendance-clean.csv | 去重后 210 条；到场人数和到场率不变 |
| attendance-corrected.csv | 移除 S0001 的两条签到，209 人到场，179 名报名者到场 |
| expected.json | 三类版本的期望指标 |

先保存原始版本，再在签到上传框导入修正版，勾选替换同类表格、确认映射、保存新版本。版本页展开行差异，显示 S0001 的旧行与新版本空记录。到场率 60% → 59.7%。未匹配反馈另提示，不继续混入到场者均分。

原样重复上传被拦截；追加不同文件中的同人记录产生跨文件重叠，处理前不能保存。展示明确的排除记录和口径，不把人工处理包装成自动识别真相。

## 自由提问（需真实模型配置）

| 输入 | 期望 |
|---|---|
| 哪些报名渠道到场率最高 | attendanceRate/channel/desc，确认后执行 |
| 各年级到场人数 | attended/grade，仅可关联报名的人群 |
| 删除渠道映射后再问渠道到场率 | 明确缺少字段，无猜测图表 |
| 活动赚了多少钱 | 不支持，需费用收入数据及相应工具 |
| 为什么朋友推荐渠道低 | 不支持因果，不给管理建议 |
| 帮我分析一下 | 提示明确问题，不随意选指标 |
| 模型输出 SQL 或未知字段 | schema 拦截，预设分析仍能用 |
| 未确认云端发送范围 | 不发模型请求 |

真实模型验收未完成，模拟模型测试不能替代线上效果。演示使用虚构数据，表头和提问不要填个人信息。

## 检查命令

`npm test` 运行 `tests/**/*.test.ts`；`npm run build` 检查 TypeScript 并生产打包。`node scripts/generate-fixtures.mjs` 重建虚构 fixture。通过项数不代表产品准确率。

赛前仍需真实脱敏数据和活动组织者验收。开发只用功能分支，通过 PR 审阅 main；不提交令牌、`.env` 或真实学生表格。
